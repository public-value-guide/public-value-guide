# Topik 5.4 — Data Sektor Publik, Interoperabilitas, lan Data Terbuka

**Data dadi aset publik mung yen dikelola kanthi apik supaya bisa dipercaya, distrukturake kanthi apik supaya bisa pindhah antarsistem sing ora tau dirancang kanggo ngobrol siji lan sijiné, lan cukup terbuka supaya wong ing njaba organisasi sing ngumpulaké data bisa nggunakaké — lan keterbukaan sing mbukak nilai iku uga sing ndadèkaké privasi wong-wong sing dijlentrehaké ing data kena risiko.**

## Apa Sebabe Iki Wigati kanggo Nilai Publik

Saben lembaga publik wis nyekel data luwih akèh tinimbang sing dienggo kanthi apik. Otoritas pajak, jaringan rumah sakit, lembaga transportasi, lan kantor tata kota lokal saben ngumpulaké informasi minangka hasil sampingan nglakokaké layanan, lan saben nemokaké, biasané kasèp, yen cathetan sing dibutuhaké kanggo mangsuli pitakonan warga utawa ngrampungaké sengketa dumunung ing sistem sing ora bisa ditakoni wong liya ing organisasi. Biayané ora abstrak: warga sing wis ngandhani siji lembaga alamaté ora kudu ngandhani maneh marang lembaga liya ing pamarentah sing padha.

Ana rong ambisi sing béda ing judhul topik iki, lan lembaga publik kerep nyampuraké. Sing kapisan yaiku interoperabilitas — nggawé data bisa pindhah kanthi andal antarsistem sing digawé mandhiri dening tim lan jaman teknologi sing béda, supaya siji bagéan pamarentah bisa tumindak adhedhasar apa sing wis dingerteni bagéan liyané. Sing kapindho yaiku keterbukaan — nerbitaké data ing njaba pamarentah kabèh, supaya wartawan, peneliti, lan warga bisa nganggo kanggo tujuan sing ora tau dikira lembaga sing nerbitaké. Interoperabilitas biasané masalah rekayasa lan pamarentahan; keterbukaan iku nilai publik kanthi dhéwé, saka kulawarga sing padha karo barang publik sing diterangaké ing Topik 1.4 — Barang Publik, Barang Pantes, lan Pluralisme Nilai, amarga data sing diterbitaké iku non-rivalrous lan angel nyegah wong saka ngaksesé yen wis dirilis, mula pasar piyambak bakal kurang nyedhiyakaké.

Loro-lorone ambisi iku bentrok karo kasunyatan katelu sing dianggep topik iki minangka ketegangan sing nyata lan durung rampung, ora masalah kanthi wangsulan rapi: data sing cukup rinci kanggo migunani kerep cukup rinci kanggo ngenali individu sing dijlentrehaké, sanajan jeneng lan pengenal sing cetha wis dibuang. Pamarentah sing nerbitaké kanthi lengkap lan pamarentah sing nglindhungi wong ing cathetané kanthi apik narik menyang arah sing béda ing tuas sing padha, lan napsu sing saya tambah kanggo data kanggo nglatih lan ngevaluasi sistem algoritmik (waca Topik 5.2 — Kecerdasan Buatan lan Pengambilan Keputusan Algoritmik ing Pamarentah) wis ngunggahaké taruhan, amarga luwih akèh pihak tinimbang sadurungé kepéngin data publik ing tingkat perincian sing paling beresiko yen dirilis. Pimpinan sing nganggep pamarentahan, interoperabilitas, lan keterbukaan minangka siji masalah, kanthi privasi minangka kendala permanèn, luwih siap nggayuh nilai topik iki tinimbang sing nganggep saben-saben piyambak.

## Konsep-Konsep Utama

**Pamarentahan data** yaiku sakumpulan hak keputusan, standar, lan akuntabilitas sing nemtokaké sapa sing oleh nggawé, ngowahi, ngakses, lan mensiunaké data organisasi, lan miturut standar kualitas apa data kudu dijaga (waca [pamarentahan data](https://en.wikipedia.org/wiki/Data_governance)). Iki beda saka manajemen data, yaiku karya operasional mindhah lan nyimpen data saben dina; pamarentahan nemtokaké aturan, manajemen nglakokaké. Lembaga publik tanpa pamarentahan data isih duwé data, nanging ora ana sing bisa nyatakaké kanthi yakin salinan cathetan warga endi sing otoritatif, utawa sapa sing tanggung jawab yen cathetan iku salah.

**Juru kelola data** yaiku individu utawa peran sing dijenengi sing tanggung jawab marang kualitas, definisi, lan panggunan sing pantes kanggo dataset tartamtu, beda saka staf teknis sing nglakokaké sistem panggonané (waca [juru kelola data](https://en.wikipedia.org/wiki/Data_steward)). Juru kelola wigati amarga kualitas data mudhun kanthi baku: kolom sing ora ana sing tanggung jawab bakal nglumpukaké entri sing ora konsisten, cathetan dobel, lan pergeseran meneng-menengan antarané apa sing dimaksudaké kolom lan apa sing sejatiné diisi staf. Nugasaké juru kelola marang dataset ngowahi kualitas data saka latihan resik-resik sok-sok dadi tanggung jawab sing terus-terusan lan kanthi jeneng.

**Interoperabilitas** yaiku kemampuan sistem sing digawé mandhiri kanggo nuker data lan nganggo kanthi bener tanpa rekayasa khusus sepisan kanggo saben pasang sistem sing kalebu (waca [interoperabilitas](https://en.wikipedia.org/wiki/Interoperability)). Iki lumaku ing telung tingkat sing gampang kecampur: interoperabilitas teknis (apa sistem bisa nyambung lan mindhah bita babar pisan, biasané liwat antarmuka pemrograman aplikasi, utawa API, cara tartamtu supaya siji piranti lunak njaluk data utawa tumindak saka liyané — waca [antarmuka pemrograman aplikasi](https://en.wikipedia.org/wiki/Application_programming_interface)); interoperabilitas semantik (apa loro sistem nduweni teges sing padha kanggo kolom bareng, kayata "kluwarga" utawa "kasus aktif"); lan interoperabilitas organisasional (apa loro organisasi sarujuk bab sebab data dienggo bareng lan sapa sing tanggung jawab marang apa sing kelakon candhaké). Pirang-pirang kegagalan interoperabilitas sing larang kelakon ing tingkat semantik utawa organisasional sanajan sambungan teknis mlaku kanthi sampurna.

**Skema umum**, utawa standar data, yaiku struktur sing disepakati lan diterbitaké kanggo nggambaraké sawijining kategori data — jeneng kolom, format, satuan, lan nilai sing diidinaké — sing diadopsi luwih saka siji sistem utawa organisasi supaya data saka siji bisa dienggo liyané tanpa terjemahan manual. Lembaga pamarentah sing ngadopsi skema bareng kanggo bab sing dhasar kayata alamat utawa status kasus ngowahi puluhan masalah terjemahan bilateral dadi siji standar sing bisa langsung diimplementasi saben sistem anyar. **Pengenal unik** sing tetep ing antarané sistem lan sajrone wektu — nomer kasus, nomer registrasi usaha, referensi warga — iku mekanisme khusus sing ngidinake cathetan bab wong utawa entitas sing padha disambungaké kanthi bener, lan kesalahan ing desain pengenal (nggunakaké ulang nomer, ngowahi format, utawa ora duwé pengenal blas) iku salah sijiné panyebab kegagalan interoperabilitas sing paling umum lan bisa dihindari.

**Metadata** yaiku data bab data — katrangan struktur, asal-usul, frekuensi pembaruan, lan teges dataset, diterbitaké bareng karo datané supaya panganggo sing ora nggawé bisa ngerti lan percaya (waca [metadata](https://en.wikipedia.org/wiki/Metadata)). Dataset sing diterbitaké tanpa metadata sing cukup meh ora bisa dienggo dening sapa wae ing njaba tim sing ngasilaké, sanajan lisènsiné terbuka; metadata iku sing ngowahi tumpukan berkas dadi bab sing bener-bener bisa dienggo ulang pihak katelu.

**Persetujuan nuker data** yaiku susunan resmi antarlembaga, utawa antarané lembaga publik lan mitra njaba, sing nemtokaké tujuan data bisa dienggo, dasar hukum kanggo nuker, suwene bisa disimpen, lan apa sing kelakon yen tujuan owah. Pambatesan tujuan — mbatesi panggunan data sing dienggo bareng marang tujuan sawijining data dikumpulaké utawa dienggo bareng — iku disiplin sing njaga persetujuan nuker data supaya ora dadi lisènsi tanpa watesan kanggo nggunakaké ulang informasi pribadi, lan ora anané iku tema sing bola-bali ing kegagalan kapercayan publik sing nglibataké data antarlembaga.

**Data terbuka** yaiku data sing disedhiyakaké kanthi bébas supaya sapa wae bisa ngakses, nganggo, lan nyebaraké maneh, kanggo tujuan apa wae, biasané bisa diwaca mesin lan dirilis miturut lisènsi sing ngidinake panggunan ulang, ora mung ndeleng (waca [data terbuka](https://en.wikipedia.org/wiki/Open_data)). Alasan nilai publiké ngetutaké logika barang publik sing diterangaké ing Topik 1.4 — Barang Publik, Barang Pantes, lan Pluralisme Nilai: yen dataset wis diterbitaké, panggunan siji wong ora nyuda panggunan wong liya, lan pamarentah kerep dadi siji-sijiné pihak sing duwé standing hukum lan skala kanggo ngumpulaké lan nerbitaké, mula pasar swasta piyambak kurang nyedhiyakaké informasi jenis iki kanthi terus-terusan. Data terbuka ngidinake akuntabilitas (wartawan lan warga mriksa klaim pamarentah dhéwé karo cathetan pamarentah dhéwé), inovasi pihak katelu (bisnis lan teknolog sipil mbangun layanan ing ndhuwur data publik sing ora bakal dibangun pamarentah dhéwé), lan keputusan publik sing luwih apik ing papan liya ing ekonomi, kabèh tanpa lembaga sing nerbitaké kudu ngira saben panggunan sadurungé.

**Identifikasi ulang** yaiku proses nyocokaké data sing dianggep anonim karo informasi liya sing kasedhiya kanggo ngerteni wong nyata endi sing dijlentrehaké sawijining cathetan, lan iku kasunyatan teknis utama sing ndadèkaké ketegangan privasi ing topik iki ora bisa dihindari, ora mung ngrepotaké (waca [identifikasi ulang data](https://en.wikipedia.org/wiki/Data_re-identification)). Mbuwang jeneng, utawa pengenal sing cetha kayata nomer asuransi nasional utawa jaminan sosial, ora ngilangaké risiko: kombinasi kuasi-pengenal kayata umur, kode pos, lan kondisi medis sing langka bisa ngenali wong sacara unik sanajan ing dataset sing ora tau nyebut jenengé, utamané yen disilangaké karo dataset liya sing diterbitaké kanthi kapisah. **K-anonimitas** iku salah siji cara formal kanggo nalar risiko iki: dataset nyukupi k-anonimitas yen saben kombinasi kolom kuasi-pengenal sing dikandhut dienggo bareng paling sethithik sawetara tartamtu, k, cathetan, mula ora ana baris tunggal sing bisa dipisahaké dadi kurang saka k wong sing mungkin (waca [k-anonimitas](https://en.wikipedia.org/wiki/K-anonymity)). **Privasi diferensial** iku pendekatan sing luwih anyar lan ketat sacara matematis sing nambah gangguan statistik sing dikalibrasi kanthi ati-ati marang dataset utawa asil kueri marang dataset iku, supaya anané utawa ora anané cathetan siji individu ngowahi output sing diterbitaké mung kanthi jumlah sing winates lan bisa dibuktèkaké, preduli apa sing wis dingerteni panyerang (waca [privasi diferensial](https://en.wikipedia.org/wiki/Differential_privacy)). **Privasi miturut desain** yaiku prinsip sing luwih jembar yen pangayoman privasi kudu dibangun menyang arsitektur sistem wiwit wiwitan, minangka setelan baku, ora ditempelaké minangka langkah panyunting sadurungé publikasi (waca [privasi miturut desain](https://en.wikipedia.org/wiki/Privacy_by_design)); nyunting pengenal sing cetha sawisé kedadeyan iku wujud paling ringkih saka disiplin iki, dudu gantiné.

## Praktik Paling Apik

1. **Tunjuk juru kelola sing tanggung jawab kanggo saben dataset sing wigati, ora mung kantor data pusat.** Kantor data bisa nyetel standar, nanging ora bisa ngerti apa kolom tartamtu ing sistem tartamtu isih tegesé padha kaya sing didefinisiaké; pertimbangan iku kagungané wong sing cedhak karo panggunan nyata data.
2. **Terbitna kanthi terbuka minangka baku, lan dokumentasiné alasan khusus saben ora nerbitaké.** Mbalik baku — mbutuhaké pembenaran kanggo nahan, dudu pembenaran kanggo nerbitaké — mungkasi sensitivitas sing asli dadi tinjauan individu, tinimbang ngidinake ati-ati ditrapaké marang kabèh tanpa pilih.
3. **Adopsi skema bareng sing wis ana sadurungé ngrancang sing anyar.** Struktur data pesenan sing pas banget kanggo siji proyek nanging ora cocog karo liyané ing pamarentah njamin biaya integrasi ing tembe mburi; priksanen apa sing wis diterbitaké sektor, yurisdiksi, utawa badan standar internasional sadurungé mbangun dhéwé.
4. **Rancangen pengenal unik sing tetep lan dikelola kanthi apik sadurungé sistem mlaku, ora sawisé.** Nambahaké skema pengenal ing cathetan sing wis nglumpuk pirang-pirang taun ing sangisoré kunci sing ora konsisten luwih larang banget tinimbang nggawé desain bener wiwit wiwitan.
5. **Gawéa pertukaran data liwat API sing dikelola, ora transfer berkas sepisan.** API sing nerapaké skema, nyathet akses, lan bisa diversi maringi titik interoperabilitas sing bisa dikendhalèkaké lan diaudit; lembar kerja sing diimel antarkantor ora maringi apa-apa saka iku lan ora ana sing sadar yen wis basi.
6. **Tulisen persetujuan nuker data sing nyebutaké tujuan, dasar hukum, lan kadaluwarsa, ora mung mekanisme teknis.** Persetujuan sing nemtokaké cara data pindhah nanging ora sebabé, utawa suwene, cenderung ngluwihi tujuan sing mbenerake lan meneng-menengan dadi idin kanggo bab sing ora diidinaké kanthi eksplisit.
7. **Anggepen de-identifikasi minangka penilaian risiko kanthi asil sisa, dudu tugas nyunting sepisan.** Takonen dataset umum utawa sing bisa dituku apa sing bisa disambungaké karo sing arep dirilis, lan ukuren risiko identifikasi ulang adhedhasar model ancaman sing realistis, dudu panyerang ideal tanpa informasi njaba.
8. **Trapna privasi diferensial utawa teknik formal sing padha kanggo rilis apa wae sing nglibataké populasi cilik utawa ciri langka.** Penekanan utawa generalisasi pengenal sing cetha ora cukup yen dataset ngandhut bab sing ora lumrah nganti bisa ngenali dhéwé, kayata kondisi langka, populasi lokal cilik, utawa transaksi nilai dhuwur.
9. **Jagaa katalog data publik sing mutakhir kanthi metadata nyata, ora mung dhaptar jeneng berkas.** Dataset sing ora bisa dingerteni panganggo potensial nganti bisa dipercaya sejatiné durung diterbitaké, sanajan lisènsiné longgar; entri katalog kudu nyebutaké teges kolom, sepira kerep dianyari, lan watesan sing dikenal.
10. **Ukuren kualitas data miturut standar sing ditemtokaké kanthi jadwal rutin, lan laporna asilé marang pemilik dataset.** Kualitas sing mung dipriksa nalika ana sing rusak mudhun kanthi ora kasat mata ing antarané; pangukuran rutin ngowahi kemunduran dadi tren sing katon lan bisa dikelola.
11. **Tinjauen saben dataset sing diterbitaké kanthi périodik kanggo nilai publik lan risiko sing isih ana.** Populasi owah, teknik identifikasi ulang saya apik, lan rilis sing aman limang taun kepungkur bisa ora aman saiki marang data sing saiki wis kasedhiya ing papan liya.
12. **Pisahna kaputusan nuker utawa nerbitaké data saka tim teknis sing mindhahaké.** Wong sing paling pantes nimbang tujuan, proporsionalitas, lan risiko privasi arang padha karo wong sing paling pantes mbangun saluran, lan nyampuraké loro peran dadi siji ndadèkaké pertimbangan sing luwih angel kurang diteliti.

## Pitakon kanggo Diskusi karo Tim

**Apa kita ngerti sistem endi sing nyekel cathetan otoritatif kanggo saben entitas data inti kita, lan apa saben wong pancèn nganggep mangkono?** Akèh organisasi duwé, sacara praktik, pirang-pirang salinan "bener" saka informasi sing padha — alamat warga ing sistem tagihan, sistem manajemen kasus, lan cathetan korespondensi, kabèh rada béda lan kabèh dienggo tumindak dening wong. Gunakna pitakon iki kanggo ndhaptar entitas inti organisasi panjenengan (warga, kasus, properti, usaha) lan ngenali, kanthi jujur, apa ana sumber otoritatif tunggal kanggo saben utawa apa staf wis meneng-menengan sinau sistem endi sing dipercaya kanggo tujuan endi. Rembugen apa sing dibutuhaké kanggo nunjuk lan nerapaké siji sumber otoritatif per entitas, lan apa sing bakal rusak ing transisi. Iki biasané luwih murah dibenerake awal tinimbang sawisé keputusan serius dijupuk adhedhasar salinan sing salah.

**Yen wong takon marang kita kenapa kudu menehi informasi sing padha marang loro bagéan organisasi kita dhéwé, apa wangsulan sing jujur?** Wangsulan sing jujur kerep yaiku "amarga sistem kita ora bisa nuker", sing iku kegagalan interoperabilitas sing didandani dadi syarat proses. Gunakna pitakon iki kanggo milih siji perjalanan layanan sing nyabrang luwih saka siji tim utawa sistem lan nelusuri, langkah demi langkah, ing ngendi fakta sing padha dicathet luwih saka sepisan. Rembugen apa panyuwunan bola-bali iku nglindhungi bab sing asli — idin anyar, langkah verifikasi — utawa mung amarga ora ana persetujuan nuker data utawa skema umum. Pikiren sepira regane, ing kapercayan warga lan wektu staf, kanggo ora ndandani setaun maneh.

**Ing ngendi wartawan utawa peneliti sing tekad bakal paling mungkin ngenali wong ing dataset sing saiki kita sebut anonim?** Akèh organisasi sing nerbitaké data sing wis de-identifikasi durung nguji kanthi kenceng marang kombinasi realistis saka kuasi-pengenal lan dataset publik liya. Gunakna pitakon iki kanggo milih dataset paling beresiko sing wis utawa bakal diterbitaké lan telusuri informasi liya apa — laporan berita lokal, dataset terbuka lembaga liya, register publik — sing bisa disambungaké marang iku. Rembugen apa pendekatan de-identifikasi saiki (penekanan, generalisasi, utawa teknik formal kayata k-anonimitas utawa privasi diferensial) bakal pancèn tahan marang kombinasi iku, lan sapa sing tanggung jawab nguji ulang nalika data njaba anyar kasedhiya.

**Sapa sing saiki nduweni wewenang kanggo ngandhakaké dataset ora kudu diterbitaké, lan apa kita yakin wewenang iku dienggo kanggo alasan sing bener?** Kabijakan terbuka minangka baku isih butuh proses pangecualian sing kredibel lan dipikir kanthi apik, lan wong sing nglakokaké kudu bisa dikenali lan tanggung jawab. Gunakna pitakon iki kanggo mriksa apa keputusan nahan ing organisasi panjenengan digawé dening peran sing dijenengi miturut kriteria kadokumentasi, utawa sacara ora resmi, dening sapa wae sing kebeneran ditakoni lan condong ati-ati. Rembugen apa tingkat nahan panjenengan katon luwih kaya pertimbangan kasus demi kasus sing ati-ati utawa refleks institusional tetep, lan apa sing bisa dituduhaké tinjauan njaba périodik marang dataset sing ditahan.

**Apa persetujuan nuker data antarlembaga kita isih dienggo kanggo tujuan sing ditulis?** Pambatesan tujuan gampang ditulis ing persetujuan lan gampang ngrosot meneng-menengan ing praktik, utamané yen dataset ketemu migunani kanggo bab sing ora tau dikira para penandatangan asliné. Gunakna pitakon iki kanggo milih rong utawa telung susunan nuker data antarlembaga sing lagi mlaku lan priksa panggunan nyata saiki marang tujuan tertulis lan tanggal kadaluwarsa. Rembugen langkah pamarentahan apa sing ilang yen ana ketidakcocokan, lan sapa sing kudu tanggung jawab nangkep pergeseran jinis iku sadurungé audit njaba utawa wartawan.

**Yen standar interoperabilitas utawa data kita dadi alangan kanggo panggunan anyar sing sah saka data kita, apa kita bakal ngerti sadurungé utawa sawisé nimbulaké cilaka nyata?** Standar sing masuk akal nalika diadopsi bisa ngeras dadi alangan nalika kabutuhan lan teknologi owah, lan organisasi arang nyetel mekanisme kanggo nyadari iki kedadeyan marang aturané dhéwé. Gunakna pitakon iki kanggo ngrembug kepriyé organisasi panjenengan saiki mriksa apa standar data, skema pengenal, utawa proses nuker isih nglayani tujuané, tinimbang mung diwarisaké lan ora dipitakoni. Pikiren apa wong-wong sing bakal nyadari yen standar wis dadi alangan — staf garis ngarep, organisasi mitra, pangembang njaba sing nganggo data terbuka panjenengan — duwé saluran nyata kanggo ngangkat, lan apa saluran iku tau pancèn ngowahi standar.

## Ing Praktik: Conto Nilai Publik

Lembaga kesejahteraan sosial regional lan otoritas kesehatan regional sing kapisah — fiktif, gambaran pola, dudu laporan bab badan nyata — wis sepuluh taun nglakokaké sistem manajemen kasus sing ora cocog, mula kluwarga sing dikenal marang loro-lorone bisa dicathet nganggo nomer referensi sing béda, tanpa cara sing andal kanggo ngandhani staf lembaga yen kluwarga sing katon ing kasus dhukungan omah iku kluwarga sing padha karo ing kasus jangkauan pediatrik. Program bareng kanggo ngenali bocah sing beresiko tiba ing celah antarané rong layanan macet bola-bali, ora amarga kurang karsa politik, nanging amarga ora ana sing bisa ngasilaké tampilan gabungan tunggal sing bisa dipercaya bab kluwarga endi sing butuh loro jinis dhukungan.

Rong lembaga pungkasané ngadopsi pengenal kluwarga bareng lan skema umum kanggo kolom sing dibutuhaké loro sistem kanggo nuker, dibangun liwat API sing dikelola, ora ekspor lembar kerja périodik sing dienggo saben sadurungé, miturut persetujuan nuker data sing nyebutaké tujuan khusus — nyelarasaké dhukungan kanggo kluwarga beresiko — lan mbutuhaké tinjauan taunan. Sajrone setaun, para pekerja kasus ing loro sisi bisa ndeleng, kanggo pisanan, kluwarga endi sing dikenal layanan liyané, lan konferensi kasus bareng sing sadurungé gumantung marang pamriksan silang manual dadi rutin. Lembaga banjur luwih adoh, nerbitaké dataset terbuka tingkat wilayah sing diagregasi sing nuduhaké jumlah kluwarga sing nampa dhukungan gabungan miturut distrik, kanggo mbantu lembaga amal lokal nargetaké jangkauané lan supaya anggota dewan sing kapilih bisa ndeleng apa program bareng nggayuh wilayah sing dituju.

Pegiat hak data lokal, kerja bareng peneliti universitas, nemokaké yen angka tingkat distrik sing diterbitaké bisa disilangaké karo dataset terbuka sing diterbitaké kanthi kapisah lan padha apik niaté saka otoritas transportasi lokal — nuduhaké aplikasi tarif bersubsidi miturut wilayah cilik — kanggo nyempitaké sawetara distrik nganti jumlah kluwarga cilik banget nganti kluwarga tartamtu bisa dikenali, utamané ing distrik deso sing jarang pendhudhuké ing ngendi loro dataset ngetung jumlah kluwarga siji digit. Ora ana dataset siji-sijiné sing mbukak identitas; digabung, ing wilayah paling sithik pendhudhuké, iya. Reaksi pisanan lembaga, narik dataset terbuka kabèh, bakal ngrusak nilai akuntabilitas lan penargetan lembaga amal sing wis diwiwiti. Sabalikné, kerja bareng pegiat sing padha, lembaga nerbitaké maneh dataset nganggo pendekatan privasi diferensial sing nambah gangguan sing dikalibrasi marang cacahan cilik, njaga manfaaté kanggo nemokaké pola regional sing jembar nalika ndadèkaké cacahan nyata distrik pendhudhuk sithik apa wae cukup ora mesthi kanggo ngalahaké serangan persilangan sing mbukak rilis asli. Kedadeyan iki dadi studi kasus sing dienggo lembaga ing pelatihan stafé candhaké, kenapa de-identifikasi kudu dinilai marang apa liya sing kasedhiya sacara umum, ora marang dataset piyambak.

## Papat Sudut Pandang Sektor

### Pamarentah Lokal

Otoritas lokal biasané nglakokaké sistem sing luwih béda, luwih lawas, lan kurang terintegrasi saben warga sing dilayani tinimbang badan nasional, amarga pirang-pirang dekade sistem departemen sing dituku dhéwé-dhéwé — omah, tata kota, sampah, perawatan sosial — arang dibangun kanggo nuker data siji lan sijiné. Iki ndadèkaké interoperabilitas perang internal sadurungé dadi perang njaba: warga sing berurusan karo telung departemen dewan ing sawijining minggu bisa nemokaké yen ora ana sing bisa ndeleng apa sing wis dingerteni liyané. Data terbuka lokal, ing sisi liya, cenderung duwé nilai sipil sing langsung banget — jadwal pangumpulan sampah, aplikasi tata kota, belanja lokal — amarga warga lan wartawan lokal nggarapé ing tingkat kekhususan sing arang ditawakaké dataset nasional, sing ngunggahaké taruhan kanggo bener ing metadata lan frekuensi pembaruan sanajan kanggo dataset sing cilik lan saben dina.

### Pamarentah Nasional

Pamarentah nasional biasané nglakokaké wangun instrumen pamarentahan data lan interoperabilitas sing paling lengkap — strategi data nasional, skema pengenal antarpamarentah, portal data terbuka sing diwajibaké, lan regulator pangayoman data khusus — nanging jumlah sistem warisan sing nglumpuk pirang-pirang dekade lan pamarentahan ndadèkaké interoperabilitas teknis tugas latar mburi sing terus-terusan lan larang, dudu proyek sepisan. Program data terbuka nasional nggawa risiko identifikasi ulang sing ora proporsional amarga dataset nasional cukup gedhé kanggo pancèn migunani lan cukup rinci, yen disambungaké karo register nasional liyané, kanggo ngenali individu; dokumen strategi data nasional sing saiki diterbitaké sawetara pamarentah saya kerep nyebut teknik pambukaan sing njaga privasi kanthi eksplisit, tinimbang nganggep de-identifikasi minangka rincian implementasi ing sangisoré kabijakan.

### Sektor Sosial lan Nirlaba

Organisasi nirlaba utawa organisasi non-pamarentah (LSM) arang tundhuk marang mandat data terbuka, nanging saya kerep ngadhepi pangarep-arep paralel saka pamodal, regulator, lan publik supaya data program dienggo bareng kanthi transparan, lan kerep nggarap populasi — korban kekerasan, wong ing kemiskinan akut, warga tanpa dokumen — sing risiko identifikasi ulang nggawa biaya pribadi luwih dhuwur tinimbang biasané kanggo populasi umum ing dataset pamarentah. Persetujuan nuker data penting banget ing kene amarga organisasi nirlaba kerep nuker data klien marang pamodal pamarentah utawa organisasi mitra miturut kontrak sing ora ditulis dhéwé, lan butuh kapasitas kanggo rundhingan pambatesan tujuan, ora mung nampa katentuan nuker data apa wae sing ditempelaké ing pendanaan. Standar interoperabilitas sing diadopsi pamodal pamarentah utawa filantropi sing luwih gedhé bisa dadi beban nyata kanggo kapasitas teknis winates organisasi cilik, sing iku biaya nyata sing pantes disebut, ora nganggep adopsi standar tanpa biaya.

### Tingkat Multilateral lan Internasional

Lembaga multilateral ngumpulaké data saka negara anggota kanthi kematangan pamarentahan, kapasitas statistik, lan rezim hukum privasi sing beda banget, sing ndadèkaké interoperabilitas semantik — sarujuk bab teges sejati kolom bareng — masalah diplomatik lan teknis sing terus-terusan; istilah sapérangan dhasar kayata "kluwarga" utawa "nganggur" didefinisiaké béda banget ing antarané negara nganti badan statistik internasional njaga kabèh standar, kayata format Statistical Data and Metadata Exchange (SDMX), mung kanggo nggawé data lintas negara pancèn bisa dibandhingaké. Data terbuka ing tingkat iki dadi barang publik sing paling cetha ing pangertèn sing diterangaké ing Topik 1.4 — Barang Publik, Barang Pantes, lan Pluralisme Nilai, amarga ora ana negara anggota tunggal sing duwé insentif kanggo mbiayai dataset komparatif global dhéwé, nanging saben negara lan peneliti oleh manfaat yen badan multilateral nerbitaké. Kuwatir kedaulatan data luwih jero ing kene tinimbang ing konteks siji negara: negara anggota bisa nolak nuker data sing sah ditahan, utawa bisa mbantah kepriyé badan multilateral nggolongaké utawa ngagregasi angka nasionalé, sing ndadèkaké pitakonan pamarentahan bab sapa sing ngontrol statistik bareng padha wigatiné karo pitakonan teknis bab kepriyé iku ditukar.

## Cara-Cara Kegagalan sing Umum

**Silo data sing meneng.** Sistem nglumpuk mandhiri ing saindhenging organisasi tanpa pengenal utawa skema bareng, lan biayané tetep didhelikake nganti kasus tartamtu — kegagalan perlindungan, audit, gangguan layanan — mbutuhaké tampilan gabungan sing jebulé mokal diasilaké kanthi cepet, ing wektu kuwi biaya silo katon sakaligus lan larang didandani ing sangisoré tekanan.

**Teater anonimisasi.** Dataset dibuwang jeneng lan pengenal sing cetha lan banjur dianggep aman diterbitaké tanpa penilaian kuasi-pengenal utawa risiko sambungan karo data liya sing kasedhiya. Biayané muncul, kerep sacara umum lan ngisin-isini, nalika peneliti, wartawan, utawa pegiat nuduhaké identifikasi ulang bisa, ing wektu kuwi kredibilitas organisasi ing privasi rusak luwih saka dataset khusus iku.

**Pamarentahan tanpa pemilik.** Kabijakan pamarentahan data ana ing kertas, nanging ora ana wong tartamtu sing tanggung jawab marang kualitas utawa kemutakhiran dataset tartamtu, mula standar mudhun meneng-menengan lan ora ana sing sadar nganti data dienggo kanggo keputusan sing sejatiné ora bisa didhukung. Iki kegagalan sing umum banget amarga dokumen kabijakan dhéwé katon lengkap, nutupi ora anané wong sing sejatiné tanggung jawab ing ngisor.

**Interoperabilitas miturut mandat, tanpa sumber daya.** Skema utawa skema pengenal bareng diwajibaké saka pusat nanging ora tau didanai kanggo tim sing diarep ngadopsi, mula kepatuhan dadi latihan kotak centhang — kolom ana sacara teknis nanging ora diisi kanthi bener — tinimbang interoperabilitas sing asli lan bisa dienggo. Biayané yaiku rasa palsu yen standar bareng ana, mung ketemu nalika ana wong pancèn nyoba ngandelaké data sing sakjané distandarisasi.

**Open-washing.** Organisasi nerbitaké dasbor lan visualisasi ringkesan lan nyebut iki data terbuka, déné dataset bisa diwaca mesin sing dibutuhaké pihak katelu kanggo mbangun bab anyar tetep ora diterbitaké utawa diterbitaké ing format sing ora ana sing bisa praktis nganggo ulang. Iki njupuk tampilan transparansi lan keterbukaan sing diterangaké ing Topik 3.4 — Akuntabilitas, Transparansi, lan Legitimasi tanpa isiné, lan kerep dikira program data terbuka sing asli amarga dasbor katon nyengsemaké.

| Sub-dimensi | Wiwitan | Pangembangan | Standardisasi | Pangelolaan | Orkestrasi |
|---|---|---|---|---|---|
| Kajuru-kelolaan lan kapemilikan data | Ora ana pemilik sing dijenengi kanggo akèh dataset; masalah kualitas ditemokaké kanthi ora sengaja | Sawetara dataset sing kondhang duwé pemilik ora resmi; kualitas beda-beda banget | Saben dataset inti duwé juru kelola sing dijenengi kanthi tanggung jawab sing ditemtokaké | Kualitas data diukur miturut standar lan dilaporaké marang juru kelola kanthi rutin | Kajuru-kelolaan nyabrang wates organisasi; dataset bareng duwé pemilik sing tanggung jawab bareng |
| Standar interoperabilitas | Sistem dibangun mandhiri, nuker data liwat ekspor manual utawa ora babar pisan | Skema bareng ana kanggo sawetara domain, diadopsi ora konsisten | Skema umum lan skema pengenal diwajibaké lan diimplementasi liwat API sing dikelola | Kinerja interoperabilitas dipantau; celah nyebabaké perbaikan lan pendanaan | Standar dikembangaké bareng organisasi mitra lan yurisdiksi liya lan disesuaikan kanthi proaktif |
| Penerbitan data terbuka | Penerbitan ad hoc, tanpa dokumentasi, lan gumantung marang inisiatif individu | Katalog data ana nanging ora lengkap utawa basi; metadata tipis | Terbuka minangka baku iku kabijakan; saben dataset sing ora diterbitaké duwé alasan kadokumentasi | Penerbitan diukur kanggo panggunan ulang lan dampak; katalog dijaga kanthi aktif | Penerbitan ngantisipasi panyuwunan njaba lan nyelarasaké karo program data terbuka badan liya |
| Pambukaan sing njaga privasi | De-identifikasi tegesé mung mbuwang pengenal sing cetha, tanpa penilaian risiko | Risiko dinilai sacara ora resmi mung kanggo rilis sing kondhang | Penilaian risiko identifikasi ulang sing ditemtokaké, kalebu risiko sambungan, mlaku sadurungé saben rilis data pribadi | Teknik formal (k-anonimitas, privasi diferensial) ditrapaké sacara proporsional lan ditinjau périodik | Risiko pambukaan dinilai ulang terus-terusan nalika dataset njaba anyar kasedhiya, lan rilis kepungkur ditinjau maneh |

## Dhaptar Pariksa

- [ ] Kenali sistem sumber otoritatif kanggo saben entitas data inti organisasi panjenengan.
- [ ] Pastèkna saben dataset sing pancèn wigati duwé juru kelola sing dijenengi lan tanggung jawab.
- [ ] Priksanen apa skema utawa standar bareng wis ana kanggo proyek data anyar sadurungé ngrancang sing pesenan.
- [ ] Tinjauen desain pengenal unik panjenengan kanggo katetepan lan konsistensi ing antarané sistem sing nganggo.
- [ ] Ganti paling ora siji pertukaran data manual utawa adhedhasar lembar kerja sing bola-bali nganggo API sing dikelola.
- [ ] Pastèkna saben persetujuan nuker data antarlembaga sing aktif nyebutaké tujuan, dasar hukum, lan kadaluwarsa, lan cocog karo panggunan nyata saiki.
- [ ] Lakonana penilaian risiko identifikasi ulang, kalebu sambungan sing masuk akal marang dataset publik liya, sadurungé nerbitaké dataset apa wae sing nglibataké informasi pribadi.
- [ ] Trapna teknik njaga privasi formal, kayata k-anonimitas utawa privasi diferensial, kanggo rilis apa wae sing nglibataké populasi cilik utawa ciri langka.
- [ ] Pastèkna katalog data terbuka panjenengan ngandhut metadata nyata lan mutakhir, ora mung jeneng berkas.
- [ ] Tinjauen dataset sing wis diterbitaké marang data njaba sing anyar kasedhiya kanggo risiko identifikasi ulang sing muncul.
- [ ] Pastèkna keputusan nahan digawé dening peran sing dijenengi lan tanggung jawab miturut kriteria kadokumentasi.
- [ ] Takonen marang tim panjenengan enem pitakon diskusi ing ndhuwur lan cathet ing ngendi wangsulan jujur beda saka sing resmi.
