# ប្រធានបទ 5.4 — ទិន្នន័យវិស័យសាធារណៈ អន្តរប្រតិបត្តិការ និងទិន្នន័យបើកចំហ

**ទិន្នន័យក្លាយជាទ្រព្យសម្បត្តិសាធារណៈ លុះត្រាតែវាត្រូវបានគ្រប់គ្រងល្អគ្រប់គ្រាន់ដើម្បីអាចទុកចិត្តបាន មានរចនាសម្ព័ន្ធល្អគ្រប់គ្រាន់ដើម្បីផ្លាស់ទីរវាងប្រព័ន្ធដែលមិនដែលត្រូវបានរចនាឡើងដើម្បីទំនាក់ទំនងគ្នា និងបើកចំហគ្រប់គ្រាន់ឱ្យអ្នកដែលនៅក្រៅអង្គភាពដែលប្រមូលវា យកទៅប្រើប្រាស់ — ហើយភាពបើកចំហដដែលដែលបើកផ្លូវឱ្យតម្លៃនោះ ក៏ជាអ្វីដែលដាក់ឯកជនភាពរបស់អ្នកដែលត្រូវបានពិពណ៌នាក្នុងទិន្នន័យ ឱ្យប្រឈមនឹងហានិភ័យដែរ។**

## ហេតុអ្វីបានជាបញ្ហានេះសំខាន់សម្រាប់តម្លៃសាធារណៈ

ស្ថាប័នសាធារណៈនីមួយៗមានទិន្នន័យច្រើនជាងអ្វីដែលខ្លួនប្រើប្រាស់បានល្អស្រាប់ហើយ។ អាជ្ញាធរពន្ធ បណ្តាញមន្ទីរពេទ្យ ទីភ្នាក់ងារដឹកជញ្ជូន និងការិយាល័យផែនការមូលដ្ឋាន សុទ្ធតែប្រមូលព័ត៌មានជាផលស្នាក់នៃការដំណើរការសេវា ហើយម្នាក់ៗរកឃើញ ជាធម្មតាយឺតពេល ថាកំណត់ត្រាដែលខ្លួនត្រូវការដើម្បីឆ្លើយសំណួររបស់ពលរដ្ឋ ឬដោះស្រាយជម្លោះ កំពុងស្ថិតនៅក្នុងប្រព័ន្ធមួយដែលគ្មានអ្នកណាផ្សេងក្នុងអង្គភាពអាចសាកសួរបាន។ ថ្លៃដើមនេះមិនមែនជារឿងអរូបីទេ៖ ពលរដ្ឋដែលបានប្រាប់អាសយដ្ឋានរបស់ខ្លួនដល់ទីភ្នាក់ងារមួយរួចហើយ មិនគួរត្រូវប្រាប់ម្តងទៀតដល់ទីភ្នាក់ងារមួយទៀតក្នុងរដ្ឋាភិបាលតែមួយនោះទេ។

មានមហិច្ឆតាពីរដាច់ដោយឡែកនៅក្នុងចំណងជើងនៃប្រធានបទនេះ ហើយស្ថាប័នសាធារណៈច្រើនតែច្រឡំវា។ មហិច្ឆតាទីមួយគឺអន្តរប្រតិបត្តិការ — ធ្វើឱ្យទិន្នន័យផ្លាស់ទីបានដោយអាចទុកចិត្តបានរវាងប្រព័ន្ធដែលក្រុម និងយុគសម័យបច្ចេកវិទ្យាផ្សេងៗគ្នាបានសាងសង់ដោយឯករាជ្យ ដើម្បីឱ្យផ្នែកមួយនៃរដ្ឋាភិបាលអាចធ្វើសកម្មភាពតាមអ្វីដែលផ្នែកមួយទៀតដឹងរួចហើយ។ មហិច្ឆតាទីពីរគឺភាពបើកចំហ — ការផ្សព្វផ្សាយទិន្នន័យទៅខាងក្រៅរដ្ឋាភិបាលទាំងស្រុង ដើម្បីឱ្យអ្នកសារព័ត៌មាន អ្នកស្រាវជ្រាវ និងពលរដ្ឋអាចប្រើវាសម្រាប់គោលបំណងដែលស្ថាប័នផ្សព្វផ្សាយមិនបានគិតទុក។ អន្តរប្រតិបត្តិការភាគច្រើនជាបញ្ហាវិស្វកម្ម និងអភិបាលកិច្ច ចំណែកភាពបើកចំហជាតម្លៃសាធារណៈដោយខ្លួនឯង ក្នុងគ្រួសារតែមួយនឹងទំនិញសាធារណៈដែលបានពិពណ៌នាក្នុង ប្រធានបទ 1.4 — ទំនិញសាធារណៈ ទំនិញគួរតម្លៃ និងពហុនិយមនៃតម្លៃ ព្រោះទិន្នន័យដែលបានផ្សព្វផ្សាយមិនមានការប្រជែងគ្នាប្រើ ហើយពិបាកនឹងដកនរណាម្នាក់ចេញនៅពេលចេញផ្សាយ ដូច្នេះទីផ្សារតែឯងនឹងផ្គត់ផ្គង់វាមិនគ្រប់គ្រាន់។

មហិច្ឆតាទាំងពីរប៉ះទង្គិចនឹងការពិតទីបីដែលប្រធានបទនេះចាត់ទុកជាភាពតានតឹងពិតប្រាកដ ដែលមិនទាន់មានចម្លើយ មិនមែនជាបញ្ហាដែលមានចម្លើយស្អាតស្អំនោះទេ៖ ទិន្នន័យលម្អិតគ្រប់គ្រាន់ដើម្បីមានប្រយោជន៍ ជារឿយៗលម្អិតគ្រប់គ្រាន់ដើម្បីកំណត់អត្តសញ្ញាណបុគ្គលដែលវាពិពណ៌នា សូម្បីតែក្រោយពេលដកឈ្មោះ និងអត្តសញ្ញាណជាក់ស្តែងចេញក៏ដោយ។ រដ្ឋាភិបាលដែលផ្សព្វផ្សាយយ៉ាងសម្បូរបែប និងរដ្ឋាភិបាលដែលការពារអ្នកក្នុងកំណត់ត្រារបស់ខ្លួនបានល្អ កំពុងទាញទៅទិសដៅផ្សេងគ្នាលើដងថ្លឹងតែមួយ ហើយតម្រូវការកើនឡើងចំពោះទិន្នន័យដើម្បីបង្ហាត់ និងវាយតម្លៃប្រព័ន្ធតាមក្បួនដោះស្រាយ (សូមមើល ប្រធានបទ 5.2 — បញ្ញាសិប្បនិមិត្ត និងការសម្រេចចិត្តតាមក្បួនដោះស្រាយក្នុងរដ្ឋាភិបាល) បានលើកកម្ពស់ភាគីពាក់ព័ន្ធ ពីព្រោះមានអ្នកសម្តែងច្រើនជាងមុនចង់បានទិន្នន័យសាធារណៈក្នុងកម្រិតលម្អិតដែលធ្វើឱ្យការចេញផ្សាយមានហានិភ័យបំផុត។ មេដឹកនាំដែលចាត់ទុកអភិបាលកិច្ច អន្តរប្រតិបត្តិការ និងភាពបើកចំហជាបញ្ហាតែមួយ ដោយមានឯកជនភាពជាឧបសគ្គអចិន្ត្រៃយ៍ ស្ថិតក្នុងទីតាំងប្រសើរជាងក្នុងការទាញយកតម្លៃនៃប្រធានបទនេះ ជាងអ្នកដែលចាត់ទុកនីមួយៗដោយឡែកពីគ្នា។

## គំនិតស្នូល

**អភិបាលកិច្ចទិន្នន័យ** គឺជាសំណុំនៃសិទ្ធិសម្រេចចិត្ត ស្តង់ដារ និងគណនេយ្យភាព ដែលកំណត់ថាអ្នកណាអាចបង្កើត ផ្លាស់ប្តូរ ចូលប្រើ និងបញ្ឈប់ទិន្នន័យរបស់អង្គភាព ហើយទិន្នន័យនោះត្រូវរក្សាតាមស្តង់ដារគុណភាពណា (សូមមើល [data governance](https://en.wikipedia.org/wiki/Data_governance))។ វាខុសពីការគ្រប់គ្រងទិន្នន័យ ដែលជាការងារប្រតិបត្តិការនៃការផ្លាស់ទី និងការរក្សាទុកទិន្នន័យប្រចាំថ្ងៃ។ អភិបាលកិច្ចកំណត់ច្បាប់ ចំណែកការគ្រប់គ្រងអនុវត្តច្បាប់ទាំងនោះ។ ស្ថាប័នសាធារណៈដែលគ្មានអភិបាលកិច្ចទិន្នន័យនៅតែមានទិន្នន័យ ប៉ុន្តែគ្មានអ្នកណាអាចនិយាយដោយទំនុកចិត្តបានថា ច្បាប់ចម្លងណានៃកំណត់ត្រារបស់ពលរដ្ឋជាច្បាប់ដែលមានសិទ្ធិអំណាច ឬអ្នកណាទទួលខុសត្រូវនៅពេលកំណត់ត្រានោះប្រែជាខុស។

**អ្នកថែរក្សាទិន្នន័យ (data steward)** គឺជាបុគ្គល ឬតួនាទីដែលមានឈ្មោះ ដែលទទួលខុសត្រូវចំពោះគុណភាព និយមន័យ និងការប្រើប្រាស់សមស្របនៃសំណុំទិន្នន័យជាក់លាក់មួយ ខុសពីបុគ្គលិកបច្ចេកទេសដែលដំណើរការប្រព័ន្ធដែលទិន្នន័យនោះស្ថិតនៅ (សូមមើល [data steward](https://en.wikipedia.org/wiki/Data_steward))។ ការថែរក្សាសំខាន់ ព្រោះគុណភាពទិន្នន័យរិចរឹលតាមលំនាំដើម៖ វាលដែលគ្មានអ្នកណាទទួលខុសត្រូវ កកកុញធាតុមិនស្របគ្នា កំណត់ត្រាស្ទួន និងការរេរាដោយស្ងាត់ៗរវាងអ្វីដែលវាលត្រូវមានន័យ និងអ្វីដែលបុគ្គលិកបញ្ចូលពិតប្រាកដ។ ការកំណត់អ្នកថែរក្សាសម្រាប់សំណុំទិន្នន័យមួយ បំប្លែងគុណភាពទិន្នន័យពីសកម្មភាពសម្អាតម្តងម្កាល ទៅជាទំនួលខុសត្រូវជាប់ឈ្មោះបន្តរហូត។

**អន្តរប្រតិបត្តិការ** គឺជាសមត្ថភាពរបស់ប្រព័ន្ធដែលសាងសង់ដោយឯករាជ្យ ក្នុងការផ្លាស់ប្តូរទិន្នន័យ និងប្រើវាបានត្រឹមត្រូវ ដោយមិនចាំបាច់មានវិស្វកម្មពិសេសម្តងគត់សម្រាប់គូប្រព័ន្ធនីមួយៗ (សូមមើល [interoperability](https://en.wikipedia.org/wiki/Interoperability))។ វាដំណើរការនៅបីកម្រិតដែលងាយច្រឡំ៖ អន្តរប្រតិបត្តិការបច្ចេកទេស (តើប្រព័ន្ធអាចតភ្ជាប់ និងផ្លាស់ទីទិន្នន័យបានឬទេ ជាទូទៅតាមរយៈចំណុចប្រទាក់កម្មវិធី ឬ API ដែលជាវិធីកំណត់សម្រាប់កម្មវិធីមួយស្នើទិន្នន័យ ឬសកម្មភាពពីកម្មវិធីមួយទៀត — សូមមើល [application programming interface](https://en.wikipedia.org/wiki/Application_programming_interface))។ អន្តរប្រតិបត្តិការផ្នែកន័យ (តើប្រព័ន្ធទាំងពីរមានន័យដូចគ្នាចំពោះវាលរួមដូចជា "គ្រួសារ" ឬ "ករណីសកម្ម" ឬទេ)។ និងអន្តរប្រតិបត្តិការផ្នែកអង្គភាព (តើអង្គភាពទាំងពីរយល់ស្របអំពីមូលហេតុនៃការចែករំលែកទិន្នន័យ និងអ្នកណាទទួលខុសត្រូវចំពោះអ្វីដែលកើតឡើងបន្ទាប់ឬទេ)។ ការបរាជ័យអន្តរប្រតិបត្តិការដែលមានថ្លៃដើមខ្ពស់ភាគច្រើនកើតឡើងនៅកម្រិតន័យ ឬអង្គភាព សូម្បីតែនៅពេលការតភ្ជាប់បច្ចេកទេសដំណើរការយ៉ាងល្អឥតខ្ចោះក៏ដោយ។

**គ្រោងរួម (common schema)** ឬស្តង់ដារទិន្នន័យ គឺជារចនាសម្ព័ន្ធដែលបានព្រមព្រៀង និងផ្សព្វផ្សាយ សម្រាប់របៀបតំណាងឱ្យប្រភេទទិន្នន័យមួយ — ឈ្មោះវាល ទម្រង់ ឯកតា និងតម្លៃដែលអនុញ្ញាត — ដែលប្រព័ន្ធ ឬអង្គភាពច្រើនទទួលយក ដើម្បីឱ្យទិន្នន័យដែលផលិតដោយមួយអាចត្រូវបានប្រើដោយមួយទៀត ដោយមិនចាំបាច់បកប្រែដោយដៃ។ ស្ថាប័នរដ្ឋាភិបាលដែលទទួលយកគ្រោងរួមសម្រាប់អ្វីដែលជាមូលដ្ឋានដូចជាអាសយដ្ឋាន ឬស្ថានភាពករណី បំប្លែងបញ្ហាបកប្រែទ្វេភាគីដែលអាចកើតមានរាប់សិប ទៅជាស្តង់ដារតែមួយដែលប្រព័ន្ធថ្មីនីមួយៗអាចអនុវត្តបានយ៉ាងសាមញ្ញ។ **លេខសម្គាល់តែមួយគត់ (unique identifier)** ដែលស្ថិតស្ថេរនៅទូទាំងប្រព័ន្ធ និងតាមពេលវេលា — លេខករណី លេខចុះបញ្ជីអាជីវកម្ម លេខយោងពលរដ្ឋ — គឺជាយន្តការជាក់លាក់ដែលអនុញ្ញាតឱ្យកំណត់ត្រាអំពីបុគ្គល ឬអង្គភាពតែមួយត្រូវបានតភ្ជាប់បានត្រឹមត្រូវ ហើយការរចនាលេខសម្គាល់ខុស (ប្រើលេខឡើងវិញ ប្តូរទម្រង់ ឬគ្មានលេខសម្គាល់សោះ) គឺជាមូលហេតុដ៏សាមញ្ញបំផុតមួយ ដែលអាចជៀសវាងបាន នៃការបរាជ័យអន្តរប្រតិបត្តិការ។

**មេតាដាតា (metadata)** គឺជាទិន្នន័យអំពីទិន្នន័យ — ការពិពណ៌នាអំពីរចនាសម្ព័ន្ធ ប្រភពដើម ភាពញឹកញាប់នៃការធ្វើបច្ចុប្បន្នភាព និងអត្ថន័យរបស់សំណុំទិន្នន័យ ដែលផ្សព្វផ្សាយរួមជាមួយទិន្នន័យ ដើម្បីឱ្យអ្នកប្រើដែលមិនបានបង្កើតវាអាចយល់ និងទុកចិត្តបាន (សូមមើល [metadata](https://en.wikipedia.org/wiki/Metadata))។ សំណុំទិន្នន័យដែលផ្សព្វផ្សាយដោយគ្មានមេតាដាតាគ្រប់គ្រាន់ ស្ទើរតែមិនអាចប្រើបានដោយអ្នកនៅខាងក្រៅក្រុមដែលផលិតវា ទោះអាជ្ញាបណ្ណបើកចំហប៉ុណ្ណាក៏ដោយ។ មេតាដាតាគឺជាអ្វីដែលបំប្លែងឯកសារទិន្នន័យដែលចាក់ចោល ឱ្យទៅជាអ្វីដែលភាគីទីបីអាចប្រើឡើងវិញបានពិតប្រាកដ។

**កិច្ចព្រមព្រៀងចែករំលែកទិន្នន័យ** គឺជាការរៀបចំជាផ្លូវការរវាងទីភ្នាក់ងារ ឬរវាងស្ថាប័នសាធារណៈ និងដៃគូខាងក្រៅ ដែលបញ្ជាក់អំពីគោលបំណងដែលទិន្នន័យអាចត្រូវបានប្រើ មូលដ្ឋានច្បាប់សម្រាប់ការចែករំលែក រយៈពេលដែលអាចរក្សាទុកបាន និងអ្វីដែលកើតឡើងប្រសិនបើគោលបំណងផ្លាស់ប្តូរ។ ការកម្រិតគោលបំណង — ការកម្រិតការប្រើប្រាស់ទិន្នន័យដែលបានចែករំលែក ត្រឹមគោលបំណងដែលវាត្រូវបានប្រមូល ឬចែករំលែក — គឺជាវិន័យដែលរារាំងមិនឱ្យកិច្ចព្រមព្រៀងចែករំលែកទិន្នន័យក្លាយជាអាជ្ញាបណ្ណគ្មានព្រំដែនក្នុងការប្រើព័ត៌មានផ្ទាល់ខ្លួនសម្រាប់គោលបំណងថ្មី ហើយការខ្វះវាជាប្រធានបទដែលកើតឡើងម្តងហើយម្តងទៀត ក្នុងការបរាជ័យទំនុកចិត្តសាធារណៈពាក់ព័ន្ធនឹងទិន្នន័យឆ្លងទីភ្នាក់ងារ។

**ទិន្នន័យបើកចំហ** គឺជាទិន្នន័យដែលត្រូវបានផ្តល់ដោយសេរីឱ្យអ្នកណាក៏ដោយចូលប្រើ ប្រើ និងចែកចាយបន្តសម្រាប់គោលបំណងណាក៏បាន ជាទូទៅអានបានដោយម៉ាស៊ីន និងចេញផ្សាយក្រោមអាជ្ញាបណ្ណដែលអនុញ្ញាតឱ្យប្រើឡើងវិញ មិនមែនគ្រាន់តែមើលប៉ុណ្ណោះទេ (សូមមើល [open data](https://en.wikipedia.org/wiki/Open_data))។ ហេតុផលតម្លៃសាធារណៈរបស់វាធ្វើតាមតក្កវិជ្ជាទំនិញសាធារណៈដែលបានរៀបរាប់ក្នុង ប្រធានបទ 1.4 — ទំនិញសាធារណៈ ទំនិញគួរតម្លៃ និងពហុនិយមនៃតម្លៃ៖ ពេលសំណុំទិន្នន័យត្រូវបានផ្សព្វផ្សាយ ការប្រើរបស់មនុស្សម្នាក់មិនកាត់បន្ថយការប្រើរបស់អ្នកដទៃទេ ហើយរដ្ឋាភិបាលជារឿយៗជាអ្នកសម្តែងតែមួយគត់ដែលមានទាំងសិទ្ធិអំណាចស្របច្បាប់ និងមាត្រដ្ឋានដើម្បីប្រមូល និងផ្សព្វផ្សាយវាតាំងពីដំបូង ដូច្នេះទីផ្សារឯកជនតែឯងផ្គត់ផ្គង់ព័ត៌មានប្រភេទនេះមិនគ្រប់គ្រាន់ជាប្រចាំ។ ទិន្នន័យបើកចំហអនុញ្ញាតឱ្យមានគណនេយ្យភាព (អ្នកសារព័ត៌មាន និងពលរដ្ឋពិនិត្យការអះអាងរបស់រដ្ឋាភិបាលទល់នឹងកំណត់ត្រារបស់ខ្លួន) នវានុវត្តន៍ដោយភាគីទីបី (អាជីវកម្ម និងអ្នកបច្ចេកវិទ្យាស៊ីវិលសាងសង់សេវាលើទិន្នន័យសាធារណៈ ដែលរដ្ឋាភិបាលខ្លួនឯងនឹងមិនសាងសង់) និងការសម្រេចចិត្តសាធារណៈប្រសើរជាងនៅកន្លែងផ្សេងក្នុងសេដ្ឋកិច្ច ទាំងអស់នេះដោយមិនចាំបាច់ឱ្យស្ថាប័នផ្សព្វផ្សាយទាយទុកគ្រប់ការប្រើប្រាស់ជាមុន។

**ការកំណត់អត្តសញ្ញាណឡើងវិញ (re-identification)** គឺជាដំណើរការផ្គូផ្គងទិន្នន័យដែលសន្មតថាអនាមិក ជាមួយព័ត៌មានផ្សេងទៀតដែលមាន ដើម្បីរកថាកំណត់ត្រាមួយពិពណ៌នាអំពីបុគ្គលពិតប្រាកដណា ហើយវាជាការពិតបច្ចេកទេសស្នូលដែលធ្វើឱ្យភាពតានតឹងឯកជនភាពក្នុងប្រធានបទនេះមិនអាចជៀសវាងបាន មិនមែនគ្រាន់តែជាភាពរំខាននោះទេ (សូមមើល [data re-identification](https://en.wikipedia.org/wiki/Data_re-identification))។ ការដកឈ្មោះ ឬអត្តសញ្ញាណជាក់ស្តែងដូចជាលេខធានារ៉ាប់រងជាតិ ឬលេខសន្តិសុខសង្គម មិនដកហានិភ័យចេញទេ៖ បន្សំនៃអត្តសញ្ញាណពាក់កណ្តាលដូចជាអាយុ លេខកូដប្រៃសណីយ៍ និងស្ថានភាពវេជ្ជសាស្ត្រកម្រ អាចកំណត់អត្តសញ្ញាណបុគ្គលម្នាក់បានតែមួយគត់ សូម្បីក្នុងសំណុំទិន្នន័យដែលមិនដែលដាក់ឈ្មោះគាត់ ជាពិសេសនៅពេលវាត្រូវបានផ្ទៀងផ្ទាត់ទល់នឹងសំណុំទិន្នន័យសាធារណៈផ្សេងទៀតដោយឡែក។ **K-anonymity** គឺជាវិធីផ្លូវការមួយក្នុងការវែកញែកអំពីហានិភ័យនេះ៖ សំណុំទិន្នន័យបំពេញ k-anonymity ប្រសិនបើគ្រប់បន្សំនៃវាលអត្តសញ្ញាណពាក់កណ្តាលដែលវាមាន ត្រូវបានចែករំលែកដោយកំណត់ត្រាយ៉ាងតិចចំនួនកំណត់មួយ k ដូច្នេះគ្មានជួរដេកណាមួយអាចត្រូវបានញែកទៅតិចជាង k បុគ្គលដែលអាចកើតមាន (សូមមើល [k-anonymity](https://en.wikipedia.org/wiki/K-anonymity))។ **ឯកជនភាពឌីផេរ៉ង់ស្យែល (differential privacy)** គឺជាវិធីសាស្ត្រថ្មីជាងដែលតឹងរ៉ឹងផ្នែកគណិតវិទ្យា ដែលបន្ថែមសំឡេងរំខានស្ថិតិដែលកែតម្រូវយ៉ាងប្រយ័ត្នប្រយែងទៅក្នុងសំណុំទិន្នន័យ ឬលទ្ធផលនៃសំណួរលើវា ដូច្នេះវត្តមាន ឬអវត្តមាននៃកំណត់ត្រារបស់បុគ្គលតែម្នាក់ ផ្លាស់ប្តូរលទ្ធផលដែលបានផ្សព្វផ្សាយត្រឹមចំនួនមានព្រំដែនដែលអាចបញ្ជាក់បាន មិនថាអ្នកវាយប្រហារដឹងអ្វីរួចហើយក៏ដោយ (សូមមើល [differential privacy](https://en.wikipedia.org/wiki/Differential_privacy))។ **ឯកជនភាពតាមការរចនា (privacy by design)** គឺជាគោលការណ៍ទូលំទូលាយជាងថា ការការពារឯកជនភាពគួរត្រូវបានបញ្ចូលក្នុងស្ថាបត្យកម្មរបស់ប្រព័ន្ធតាំងពីដំបូង ជាការកំណត់លំនាំដើម ជាជាងបន្ថែមជាជំហានលុបមុនពេលផ្សព្វផ្សាយ (សូមមើល [privacy by design](https://en.wikipedia.org/wiki/Privacy_by_design))។ ការលុបអត្តសញ្ញាណជាក់ស្តែងក្រោយពេលកើតហេតុ គឺជាទម្រង់ខ្សោយបំផុតនៃវិន័យនេះ មិនមែនជាអ្វីជំនួសវាទេ។

## ការអនុវត្តល្អបំផុត

1. **សូមតែងតាំងអ្នកថែរក្សាដែលទទួលខុសត្រូវសម្រាប់គ្រប់សំណុំទិន្នន័យដែលសំខាន់ មិនមែនត្រឹមតែការិយាល័យទិន្នន័យកណ្តាលប៉ុណ្ណោះទេ។** ការិយាល័យទិន្នន័យអាចកំណត់ស្តង់ដារ ប៉ុន្តែវាមិនអាចដឹងថា វាលជាក់លាក់មួយក្នុងប្រព័ន្ធជាក់លាក់មួយ នៅតែមានអត្ថន័យដូចដែលបានកំណត់ឬអត់ទេ។ ការវិនិច្ឆ័យនោះជារបស់នរណាម្នាក់ដែលនៅជិតការប្រើប្រាស់ជាក់ស្តែងនៃទិន្នន័យ។
2. **សូមផ្សព្វផ្សាយជាលំនាំដើមឱ្យបើកចំហ ហើយកត់ត្រាហេតុផលជាក់លាក់ ពេលណាដែលមិនផ្សព្វផ្សាយ។** ការបញ្ច្រាសលំនាំដើម — តម្រូវឱ្យមានហេតុផលដើម្បីរក្សាទុកមិនផ្សព្វផ្សាយ ជំនួសឱ្យហេតុផលដើម្បីផ្សព្វផ្សាយ — លើកឡើងភាពរសើបពិតប្រាកដសម្រាប់ការពិនិត្យនីមួយៗ ជំនួសឱ្យការបណ្តោយឱ្យការប្រុងប្រយ័ត្នអនុវត្តលើអ្វីៗទាំងអស់ដោយមិនប្រកាន់។
3. **សូមទទួលយកគ្រោងរួមដែលមានស្រាប់ មុនរចនាគ្រោងថ្មី។** រចនាសម្ព័ន្ធទិន្នន័យតាមតម្រូវការដែលសមនឹងគម្រោងតែមួយយ៉ាងល្អឥតខ្ចោះ ប៉ុន្តែមិនត្រូវនឹងអ្វីផ្សេងក្នុងរដ្ឋាភិបាល ធានាថ្លៃដើមបញ្ចូលគ្នានៅពេលអនាគត។ សូមពិនិត្យថាតើវិស័យ ដែនសមត្ថកិច្ច ឬស្ថាប័នស្តង់ដារអន្តរជាតិរបស់អ្នក បានផ្សព្វផ្សាយអ្វីរួចហើយ មុនសាងសង់ផ្ទាល់ខ្លួន។
4. **សូមរចនាលេខសម្គាល់តែមួយគត់ដែលស្ថិតស្ថេរ និងមានអភិបាលកិច្ចល្អ មុនប្រព័ន្ធចាប់ផ្តើមដំណើរការ មិនមែនក្រោយនោះទេ។** ការដាក់គ្រោងលេខសម្គាល់ទៅលើកំណត់ត្រាដែលបានកកកុញច្រើនឆ្នាំក្រោមសោមិនស្របគ្នា មានតម្លៃថ្លៃជាងការរចនាឱ្យត្រឹមត្រូវតាំងពីដំបូងយ៉ាងខ្លាំង។
5. **សូមសាងសង់ការផ្លាស់ប្តូរទិន្នន័យតាមរយៈ API ដែលមានអភិបាលកិច្ច ជាជាងការផ្ទេរឯកសារតាមឱកាស។** API ដែលអនុវត្តគ្រោង កត់ត្រាការចូលប្រើ និងអាចមានកំណែ ផ្តល់ឱ្យអ្នកនូវចំណុចអន្តរប្រតិបត្តិការដែលគ្រប់គ្រងបាន និងអាចសវនកម្មបាន។ សៀវភៅបញ្ជីដែលផ្ញើតាមអ៊ីមែលរវាងក្រសួង មិនផ្តល់អ្វីទាំងនោះទេ ហើយគ្មានអ្នកណាកត់សម្គាល់នៅពេលវាហួសសម័យ។
6. **សូមសរសេរកិច្ចព្រមព្រៀងចែករំលែកទិន្នន័យដែលបញ្ជាក់គោលបំណង មូលដ្ឋានច្បាប់ និងកាលបរិច្ឆេទផុតកំណត់ មិនមែនត្រឹមតែយន្តការបច្ចេកទេសប៉ុណ្ណោះទេ។** កិច្ចព្រមព្រៀងដែលបញ្ជាក់ពីរបៀបដែលទិន្នន័យផ្លាស់ទី ប៉ុន្តែមិនបញ្ជាក់មូលហេតុ ឬរយៈពេលប៉ុន្មាន ទំនងជាមានអាយុកាលវែងជាងគោលបំណងដែលបញ្ជាក់វា ហើយក្លាយជាការអនុញ្ញាតសម្រាប់អ្វីមួយដែលគ្មានអ្នកណាបានអនុញ្ញាតជាក់លាក់ដោយស្ងាត់ៗ។
7. **សូមចាត់ទុកការលុបអត្តសញ្ញាណជាការវាយតម្លៃហានិភ័យដែលមានលទ្ធផលសេសសល់ មិនមែនជាកិច្ចការលុបម្តងគត់ទេ។** សូមសួរថាសំណុំទិន្នន័យសាធារណៈ ឬអាចទិញបានផ្សេងទៀតណាខ្លះអាចត្រូវបានតភ្ជាប់ទល់នឹងសំណុំដែលអ្នកហៀបនឹងចេញផ្សាយ ហើយកំណត់ទំហំហានិភ័យនៃការកំណត់អត្តសញ្ញាណឡើងវិញ ទល់នឹងគំរូការគំរាមកំហែងប្រាកដនិយមនោះ មិនមែនទល់នឹងអ្នកវាយប្រហារឧត្តមគតិដែលគ្មានព័ត៌មានពីខាងក្រៅនោះទេ។
8. **សូមអនុវត្តឯកជនភាពឌីផេរ៉ង់ស្យែល ឬបច្ចេកទេសផ្លូវការស្មើគ្នា លើការចេញផ្សាយណាមួយដែលពាក់ព័ន្ធនឹងចំនួនប្រជាជនតូច ឬលក្ខណៈកម្រ។** ការលុប ឬធ្វើទូទៅអត្តសញ្ញាណជាក់ស្តែងដោយសាមញ្ញ មិនគ្រប់គ្រាន់ ពេលសំណុំទិន្នន័យមានអ្វីមួយមិនធម្មតាគ្រប់គ្រាន់ដើម្បីកំណត់អត្តសញ្ញាណដោយខ្លួនឯង ដូចជាស្ថានភាពកម្រ ចំនួនប្រជាជនមូលដ្ឋានតូច ឬប្រតិបត្តិការតម្លៃខ្ពស់។
9. **សូមរក្សាកាតាឡុកទិន្នន័យសាធារណៈដែលទាន់សម័យ ជាមួយមេតាដាតាពិតប្រាកដ មិនមែនគ្រាន់តែបញ្ជីឈ្មោះឯកសារទេ។** សំណុំទិន្នន័យដែលអ្នកប្រើសក្តានុពលមិនអាចយល់ឱ្យបានល្អគ្រប់គ្រាន់ដើម្បីទុកចិត្ត គឺស្មើនឹងមិនបានផ្សព្វផ្សាយ ទោះអាជ្ញាបណ្ណអនុញ្ញាតប៉ុណ្ណាក៏ដោយ។ ធាតុកាតាឡុកគួរប្រាប់ថាវាលមានន័យអ្វី ធ្វើបច្ចុប្បន្នភាពញឹកប៉ុណ្ណា និងដែនកំណត់ដែលដឹងរបស់វាជាអ្វី។
10. **សូមវាស់វែងគុណភាពទិន្នន័យតាមស្តង់ដារកំណត់ តាមកាលវិភាគជាប្រចាំ ហើយរាយការណ៍លទ្ធផលដល់ម្ចាស់សំណុំទិន្នន័យ។** គុណភាពដែលត្រួតពិនិត្យតែនៅពេលមានអ្វីខូច រិចរឹលដោយមើលមិនឃើញក្នុងអំឡុងពេលវែងចន្លោះនោះ។ ការវាស់វែងជាប្រចាំបំប្លែងការរិចរឹលទៅជានិន្នាការដែលមើលឃើញ និងគ្រប់គ្រងបាន។
11. **សូមពិនិត្យសំណុំទិន្នន័យដែលបានផ្សព្វផ្សាយនីមួយៗជាប្រចាំ ចំពោះតម្លៃសាធារណៈដែលនៅបន្ត និងហានិភ័យដែលនៅបន្ត។** ចំនួនប្រជាជនផ្លាស់ប្តូរ បច្ចេកទេសកំណត់អត្តសញ្ញាណឡើងវិញប្រសើរឡើង ហើយការចេញផ្សាយដែលមានសុវត្ថិភាពកាលពីប្រាំឆ្នាំមុន អាចមិនមានសុវត្ថិភាពនៅថ្ងៃនេះ ទល់នឹងទិន្នន័យដែលទើបមានថ្មីនៅកន្លែងផ្សេង។
12. **សូមញែកការសម្រេចចិត្តចែករំលែក ឬផ្សព្វផ្សាយទិន្នន័យ ចេញពីក្រុមបច្ចេកទេសដែលផ្លាស់ទីវា។** អ្នកដែលស្ថិតក្នុងទីតាំងល្អបំផុតក្នុងការវិនិច្ឆ័យគោលបំណង សមាមាត្រ និងហានិភ័យឯកជនភាព កម្រជាអ្នកដែលស្ថិតក្នុងទីតាំងល្អបំផុតក្នុងការសាងសង់បំពង់ទិន្នន័យ ហើយការបញ្ចូលតួនាទីទាំងពីរជាមួយគ្នា ទុកការវិនិច្ឆ័យដែលពិបាកជាងឱ្យមានការពិនិត្យតិចតួច។

## សំណួរសម្រាប់ពិភាក្សាជាមួយក្រុម

**តើយើងដឹងទេថាប្រព័ន្ធណាមួយរក្សាកំណត់ត្រាដែលមានសិទ្ធិអំណាចសម្រាប់អង្គភាពទិន្នន័យស្នូលនីមួយៗរបស់យើង ហើយតើគ្រប់គ្នាពិតជាចាត់ទុកវាបែបនោះឬទេ?** អង្គការជាច្រើនមានក្នុងការអនុវត្តជាក់ស្តែងនូវច្បាប់ចម្លង "ពិត" ច្រើននៃព័ត៌មានដូចគ្នា — អាសយដ្ឋានរបស់ពលរដ្ឋក្នុងប្រព័ន្ធវិក្កយបត្រ ប្រព័ន្ធគ្រប់គ្រងករណី និងកំណត់ហេតុឯកសារឆ្លើយឆ្លង ដែលខុសគ្នាបន្តិចបន្តួចទាំងអស់ ហើយមានអ្នកធ្វើសកម្មភាពតាមនីមួយៗ។ សូមប្រើសំណួរនេះដើម្បីរាយបញ្ជីអង្គភាពស្នូលរបស់អង្គការអ្នក (ពលរដ្ឋ ករណី អចលនវត្ថុ អាជីវកម្ម) ហើយកំណត់ដោយស្មោះត្រង់ថា តើមានប្រភពមានសិទ្ធិអំណាចតែមួយសម្រាប់នីមួយៗឬអត់ ឬបុគ្គលិកបានរៀនដោយស្ងាត់ៗថាត្រូវទុកចិត្តប្រព័ន្ធណាសម្រាប់គោលបំណងណា។ សូមពិភាក្សាអំពីអ្វីដែលត្រូវការដើម្បីកំណត់ និងអនុវត្តប្រភពមានសិទ្ធិអំណាចមួយសម្រាប់អង្គភាពនីមួយៗ និងអ្វីដែលនឹងខូចក្នុងអំឡុងពេលផ្លាស់ប្តូរ។ ជាធម្មតាការនេះមានតម្លៃថោកជាងក្នុងការដោះស្រាយឆាប់ ជាងក្រោយពេលការសម្រេចចិត្តធ្ងន់ធ្ងរត្រូវបានធ្វើលើច្បាប់ចម្លងខុស។

**ប្រសិនបើមនុស្សម្នាក់សួរយើងថាហេតុអ្វីបានជាគាត់ត្រូវផ្តល់ព័ត៌មានដូចគ្នាដល់ពីរផ្នែកនៃអង្គការរបស់យើងផ្ទាល់ តើចម្លើយស្មោះត្រង់របស់យើងនឹងជាអ្វី?** ចម្លើយស្មោះត្រង់ជារឿយៗគឺ "ព្រោះប្រព័ន្ធរបស់យើងមិនអាចផ្លាស់ប្តូរវាបាន" ដែលជាការបរាជ័យអន្តរប្រតិបត្តិការដែលស្លៀកពាក់ជាតម្រូវការនីតិវិធី។ សូមប្រើសំណួរនេះដើម្បីជ្រើសរើសដំណើរសេវាមួយដែលលាតសន្ធឹងលើសពីក្រុម ឬប្រព័ន្ធមួយ ហើយតាមដានជាជំហានៗថា ការពិតដូចគ្នាត្រូវបានចាប់យកច្រើនជាងមួយដងនៅកន្លែងណា។ សូមពិភាក្សាថាតើការស្នើសុំម្តងទៀតកំពុងការពារអ្វីមួយពិតប្រាកដ — ការយល់ព្រមថ្មី ជំហានផ្ទៀងផ្ទាត់ — ឬគ្រាន់តែជាអវត្តមាននៃកិច្ចព្រមព្រៀងចែករំលែកទិន្នន័យ ឬគ្រោងរួម។ សូមពិចារណាថាតើវានឹងមានថ្លៃដើមប៉ុណ្ណា ទាំងទំនុកចិត្តពលរដ្ឋ និងពេលវេលាបុគ្គលិក ប្រសិនបើទុកវាមិនដោះស្រាយមួយឆ្នាំទៀត។

**តើអ្នកសារព័ត៌មាន ឬអ្នកស្រាវជ្រាវដែលប្តេជ្ញាចិត្តទំនងជាអាចកំណត់អត្តសញ្ញាណនរណាម្នាក់ឡើងវិញបាននៅកន្លែងណាក្នុងសំណុំទិន្នន័យដែលយើងហៅថាអនាមិកនាពេលបច្ចុប្បន្ន?** អង្គការភាគច្រើនដែលផ្សព្វផ្សាយទិន្នន័យលុបអត្តសញ្ញាណ មិនទាន់បានសាកល្បងកម្រិតខ្ពស់ទល់នឹងបន្សំប្រាកដនិយមនៃអត្តសញ្ញាណពាក់កណ្តាល និងសំណុំទិន្នន័យសាធារណៈផ្សេងទៀតទេ។ សូមប្រើសំណួរនេះដើម្បីជ្រើសរើសសំណុំទិន្នន័យដែលមានហានិភ័យខ្ពស់បំផុតដែលបានផ្សព្វផ្សាយ ឬជិតផ្សព្វផ្សាយ ហើយពិនិត្យថាព័ត៌មានផ្សេងទៀតអ្វីខ្លះ — របាយការណ៍ព័ត៌មានមូលដ្ឋាន សំណុំទិន្នន័យបើកចំហរបស់ទីភ្នាក់ងារផ្សេង បញ្ជីសាធារណៈ — អាចទំនងត្រូវបានតភ្ជាប់ទល់នឹងវា។ សូមពិភាក្សាថាតើវិធីសាស្ត្រលុបអត្តសញ្ញាណបច្ចុប្បន្នរបស់អ្នក (ការលុប ការធ្វើទូទៅ ឬបច្ចេកទេសផ្លូវការដូចជា k-anonymity ឬឯកជនភាពឌីផេរ៉ង់ស្យែល) ពិតជាអាចទប់ទល់នឹងបន្សំនោះបានឬទេ ហើយអ្នកណាទទួលខុសត្រូវក្នុងការសាកល្បងឡើងវិញនៅពេលទិន្នន័យខាងក្រៅថ្មីមានកើតឡើង។

**តើនរណាមានសិទ្ធិអំណាចបច្ចុប្បន្នក្នុងការនិយាយថាសំណុំទិន្នន័យមួយមិនគួរត្រូវបានផ្សព្វផ្សាយ ហើយតើយើងមានទំនុកចិត្តថាសិទ្ធិអំណាចនោះកំពុងត្រូវបានប្រើសម្រាប់ហេតុផលត្រឹមត្រូវឬទេ?** គោលនយោបាយបើកចំហជាលំនាំដើម នៅតែត្រូវការដំណើរការលើកលែងដែលគួរឱ្យជឿជាក់ និងមានហេតុផលល្អ ហើយអ្នកអនុវត្តវាគួរតែអាចកំណត់អត្តសញ្ញាណបាន និងទទួលខុសត្រូវ។ សូមប្រើសំណួរនេះដើម្បីពិនិត្យថាតើការសម្រេចមិនផ្សព្វផ្សាយក្នុងអង្គការរបស់អ្នក ត្រូវបានធ្វើដោយតួនាទីមានឈ្មោះទល់នឹងលក្ខណៈវិនិច្ឆ័យដែលមានឯកសារ ឬដោយក្រៅផ្លូវការ ដោយអ្នកណាដែលត្រូវបានសួរ ហើយបែរទៅរកការប្រុងប្រយ័ត្ន។ សូមពិភាក្សាថាតើអត្រានៃការរក្សាទុកមិនផ្សព្វផ្សាយរបស់អ្នកមើលទៅដូចការវិនិច្ឆ័យប្រយ័ត្នប្រយែងតាមករណីនីមួយៗ ឬជាប្រតិកម្មស្វ័យប្រវត្តិរបស់ស្ថាប័ន និងអ្វីដែលការពិនិត្យខាងក្រៅតាមកាលកំណត់នៃសំណុំទិន្នន័យដែលបានរក្សាទុកអាចបង្ហាញ។

**តើកិច្ចព្រមព្រៀងចែករំលែកទិន្នន័យរវាងទីភ្នាក់ងាររបស់យើង នៅតែត្រូវបានប្រើសម្រាប់គោលបំណងដែលវាត្រូវបានសរសេរសម្រាប់ឬទេ?** ការកម្រិតគោលបំណងងាយនិយាយក្នុងកិច្ចព្រមព្រៀង ហើយងាយរលួយដោយស្ងាត់ៗក្នុងការអនុវត្ត ជាពិសេសនៅពេលសំណុំទិន្នន័យបង្ហាញថាមានប្រយោជន៍សម្រាប់អ្វីមួយដែលភាគីចុះហត្ថលេខាដើមមិនបានគិតទុក។ សូមប្រើសំណួរនេះដើម្បីជ្រើសរើសការរៀបចំចែករំលែកទិន្នន័យអន្តរទីភ្នាក់ងារដែលកំពុងដំណើរការពីរ ឬបីបន្ថែម ហើយពិនិត្យការប្រើប្រាស់បច្ចុប្បន្នជាក់ស្តែងទល់នឹងគោលបំណងដែលបានសរសេរ និងកាលបរិច្ឆេទផុតកំណត់។ សូមពិភាក្សាថាជំហានអភិបាលកិច្ចអ្វីដែលបាត់ ប្រសិនបើរកឃើញភាពមិនត្រូវគ្នា និងអ្នកណាគួរទទួលខុសត្រូវក្នុងការចាប់បានការរេរាបែបនោះ មុនសវនកម្មខាងក្រៅ ឬអ្នកសារព័ត៌មានធ្វើ។

អាជ្ញាធរមូលដ្ឋានជាទូទៅដំណើរការប្រព័ន្ធខុសគ្នាច្រើនជាង ចាស់ជាង និងមានសមាហរណកម្មតិចជាង ក្នុងមួយអ្នករស់នៅដែលបម្រើ ជាងស្ថាប័នជាតិ ព្រោះប្រព័ន្ធនាយកដ្ឋានដែលទិញដោយឡែកពីគ្នាអស់ច្រើនទសវត្សរ៍ — លំនៅដ្ឋាន ផែនការ កាកសំណល់ អន្តរាគមន៍សង្គម — កម្រត្រូវបានសាងសង់ដើម្បីចែករំលែកទិន្នន័យជាមួយគ្នា។ នេះធ្វើឱ្យអន្តរប្រតិបត្តិការជាសមរភូមិផ្ទៃក្នុងពិតប្រាកដ មុននឹងវាជាសមរភូមិខាងក្រៅ៖ អ្នករស់នៅដែលទាក់ទងនាយកដ្ឋានក្រុងបីក្នុងមួយសប្តាហ៍ អាចរកឃើញថាគ្មានមួយណាអាចមើលឃើញអ្វីដែលអ្នកដទៃដឹងរួចហើយ។ ទិន្នន័យបើកចំហមូលដ្ឋាន ទន្ទឹមនេះ ទំនងមានតម្លៃស៊ីវិលដោយផ្ទាល់ខុសពីធម្មតា — កាលវិភាគប្រមូលសំរាម ពាក្យសុំអនុញ្ញាតផែនការ ការចំណាយមូលដ្ឋាន — ព្រោះអ្នករស់នៅ និងអ្នកសារព័ត៌មានមូលដ្ឋានចូលរួមជាមួយវាក្នុងកម្រិតជាក់លាក់ ដែលសំណុំទិន្នន័យជាតិកម្របានផ្តល់ ដែលលើកកម្ពស់ភាគីពាក់ព័ន្ធក្នុងការធ្វើឱ្យមេតាដាតា និងភាពញឹកញាប់នៃការធ្វើបច្ចុប្បន្នភាពត្រឹមត្រូវ សូម្បីសម្រាប់សំណុំទិន្នន័យសាមញ្ញប្រចាំថ្ងៃក៏ដោយ។

### រដ្ឋាភិបាលជាតិ

រដ្ឋាភិបាលជាតិជាទូទៅដំណើរការឧបករណ៍អភិបាលកិច្ចទិន្នន័យ និងអន្តរប្រតិបត្តិការពេញលេញបំផុត — យុទ្ធសាស្ត្រទិន្នន័យជាតិ គ្រោងលេខសម្គាល់ឆ្លងរដ្ឋាភិបាល វិបផតថលទិន្នន័យបើកចំហដែលកំណត់ជាកាតព្វកិច្ច និងនិយតកររក្សាទិន្នន័យឯកទេស — ប៉ុន្តែចំនួនដ៏ច្រើននៃប្រព័ន្ធបេតិកភណ្ឌដែលកកកុញអស់ច្រើនទសវត្សរ៍ និងរដ្ឋបាល ធ្វើឱ្យអន្តរប្រតិបត្តិការបច្ចេកទេសជាកិច្ចការផ្ទៃខាងក្រោយដែលស្ថិតស្ថេរ និងថ្លៃ មិនមែនជាគម្រោងម្តងគត់។ កម្មវិធីទិន្នន័យបើកចំហជាតិមានហានិភ័យកំណត់អត្តសញ្ញាណឡើងវិញមិនសមាមាត្រ ពិតជាព្រោះសំណុំទិន្នន័យជាតិធំគ្រប់គ្រាន់ដើម្បីមានតម្លៃពិតប្រាកដ និងលម្អិតគ្រប់គ្រាន់ ពេលតភ្ជាប់ទល់នឹងបញ្ជីជាតិផ្សេងទៀត ដើម្បីកំណត់អត្តសញ្ញាណបុគ្គល។ ឯកសារយុទ្ធសាស្ត្រទិន្នន័យជាតិដែលរដ្ឋាភិបាលជាច្រើនឥឡូវផ្សព្វផ្សាយ ចេះតែបញ្ចេញឈ្មោះបច្ចេកទេសបង្ហាញដែលរក្សាឯកជនភាពយ៉ាងច្បាស់លាស់ ជាជាងចាត់ទុកការលុបអត្តសញ្ញាណជាព័ត៌មានលម្អិតអនុវត្តនៅក្រោមការជូនដំណឹងគោលនយោបាយ។

### វិស័យសង្គម និងវិស័យមិនស្វែងរកប្រាក់ចំណេញ

អង្គការមិនស្វែងរកប្រាក់ចំណេញ ឬអង្គការក្រៅរដ្ឋាភិបាល (NGO) កម្រស្ថិតក្រោមអាណត្តិទិន្នន័យបើកចំហ ប៉ុន្តែកាន់តែប្រឈមនឹងការរំពឹងទុកស្របគ្នាពីអ្នកផ្តល់មូលនិធិ និយតករ និងសាធារណជនថា ទិន្នន័យកម្មវិធីត្រូវបានចែករំលែកដោយតម្លាភាព ហើយវាច្រើនតែធ្វើការជាមួយប្រជាជន — អ្នករួចជីវិតពីអំពើហិង្សា មនុស្សក្នុងភាពក្រីក្រធ្ងន់ធ្ងរ អ្នករស់នៅគ្មានឯកសារ — ដែលហានិភ័យកំណត់អត្តសញ្ញាណឡើងវិញមានថ្លៃដើមផ្ទាល់ខ្លួនខ្ពស់ជាងប្រជាជនទូទៅក្នុងសំណុំទិន្នន័យរដ្ឋាភិបាលយ៉ាងខ្លាំង។ កិច្ចព្រមព្រៀងចែករំលែកទិន្នន័យមានសារៈសំខាន់មិនសមាមាត្រនៅទីនេះ ព្រោះអង្គការមិនស្វែងរកប្រាក់ចំណេញច្រើនតែចែករំលែកទិន្នន័យអតិថិជនជាមួយអ្នកផ្តល់មូលនិធិរដ្ឋាភិបាល ឬអង្គការដៃគូក្រោមកិច្ចសន្យាដែលខ្លួនមិនបានសរសេរ ហើយវាត្រូវការសមត្ថភាពក្នុងការចរចាការកម្រិតគោលបំណង ជំនួសឱ្យការទទួលយកលក្ខខណ្ឌចែករំលែកទិន្នន័យណាដែលភ្ជាប់នឹងមូលនិធិ។ ស្តង់ដារអន្តរប្រតិបត្តិការដែលទទួលយកដោយអ្នកផ្តល់មូលនិធិរដ្ឋាភិបាល ឬសប្បុរសធម៌ធំៗ អាចជាបន្ទុកពិតប្រាកដលើសមត្ថភាពបច្ចេកទេសមានកម្រិតរបស់អង្គការតូចមួយ ដែលជាថ្លៃដើមពិតប្រាកដដែលគួរបញ្ជាក់ ជាជាងចាត់ទុកការទទួលយកស្តង់ដារថាគ្មានថ្លៃដើម។

### កម្រិតពហុភាគី និងអន្តរជាតិ

ស្ថាប័នពហុភាគីប្រមូលទិន្នន័យទូទាំងរដ្ឋសមាជិកដែលមានភាពចាស់ទុំអភិបាលកិច្ច សមត្ថភាពស្ថិតិ និងរបបច្បាប់ឯកជនភាពខុសគ្នាខ្លាំង ដែលធ្វើឱ្យអន្តរប្រតិបត្តិការផ្នែកន័យ — ការព្រមព្រៀងថាវាលរួមមានន័យអ្វីពិតប្រាកដ — ជាបញ្ហាការទូតស្មើនឹងបច្ចេកទេសដែលស្ថិតស្ថេរ។ ពាក្យសាមញ្ញដូចជា "គ្រួសារ" ឬ "គ្មានការងារធ្វើ" ត្រូវបានកំណត់ខុសគ្នាគ្រប់គ្រាន់ទូទាំងប្រទេស ដែលស្ថាប័នស្ថិតិអន្តរជាតិថែរក្សាស្តង់ដារទាំងមូល ដូចជាទម្រង់ Statistical Data and Metadata Exchange (SDMX) សុទ្ធសាធដើម្បីធ្វើឱ្យទិន្នន័យឆ្លងប្រទេសអាចប្រៀបធៀបបានពិតប្រាកដ។ ទិន្នន័យបើកចំហនៅកម្រិតនេះដើរតួជាទំនិញសាធារណៈច្បាស់លាស់ជាពិសេស តាមន័យដែលបានរៀបរាប់ក្នុង ប្រធានបទ 1.4 — ទំនិញសាធារណៈ ទំនិញគួរតម្លៃ និងពហុនិយមនៃតម្លៃ ព្រោះគ្មានរដ្ឋសមាជិកណាមួយមានកត្តាជំរុញឱ្យផ្តល់មូលនិធិសំណុំទិន្នន័យប្រៀបធៀបសកលដោយខ្លួនឯង ប៉ុន្តែរដ្ឋ និងអ្នកស្រាវជ្រាវគ្រប់រូបទទួលអត្ថប្រយោជន៍ពេលស្ថាប័នពហុភាគីផ្សព្វផ្សាយមួយ។ ក្តីបារម្ភអធិបតេយ្យទិន្នន័យកាន់តែជ្រៅនៅទីនេះជាងបរិបទប្រទេសតែមួយ៖ រដ្ឋសមាជិកអាចតទល់នឹងការចែករំលែកទិន្នន័យដែលខ្លួនមានសិទ្ធិស្របច្បាប់រក្សាទុក ឬអាចជំទាស់ថាស្ថាប័នពហុភាគីបានចាត់ថ្នាក់ ឬបូកសរុបតួលេខជាតិរបស់ខ្លួនយ៉ាងដូចម្តេច ដែលធ្វើឱ្យសំណួរអភិបាលកិច្ចថាអ្នកណាគ្រប់គ្រងស្ថិតិរួមមួយ មានផលវិបាកដូចសំណួរបច្ចេកទេសអំពីរបៀបផ្លាស់ប្តូរវា។

## ទម្រង់នៃការបរាជ័យដែលជួបញឹកញាប់

**ឃ្លាំងទិន្នន័យដាច់ដោយឡែកដោយស្ងាត់ៗ។** ប្រព័ន្ធកកកុញដោយឯករាជ្យនៅទូទាំងអង្គការ ដោយគ្មានលេខសម្គាល់ ឬគ្រោងរួម ហើយថ្លៃដើមនៅតែលាក់ រហូតដល់ករណីជាក់លាក់មួយ — ការបរាជ័យការពារ សវនកម្ម ការដាច់ដំណើរការសេវា — តម្រូវទិដ្ឋភាពរួមបញ្ចូលគ្នា ដែលប្រែជាមិនអាចផលិតបានយ៉ាងរហ័ស នៅពេលនោះថ្លៃដើមនៃឃ្លាំងដាច់ដោយឡែកក្លាយជាមើលឃើញភ្លាមៗទាំងអស់ និងថ្លៃក្នុងការជួសជុលក្រោមសម្ពាធ។

**ល្ខោននៃភាពអនាមិក (anonymization theater)។** សំណុំទិន្នន័យត្រូវបានដកឈ្មោះ និងអត្តសញ្ញាណជាក់ស្តែងចេញ ហើយបន្ទាប់មកត្រូវបានចាត់ទុកថាមានសុវត្ថិភាពក្នុងការផ្សព្វផ្សាយ ដោយគ្មានការវាយតម្លៃអត្តសញ្ញាណពាក់កណ្តាល ឬហានិភ័យតភ្ជាប់ទល់នឹងទិន្នន័យផ្សេងទៀតដែលមាន។ ថ្លៃដើមលេចចេញ ជារឿយៗជាសាធារណៈ និងគួរឱ្យអាម៉ាស់ នៅពេលអ្នកស្រាវជ្រាវ អ្នកសារព័ត៌មាន ឬអ្នកតស៊ូមតិបង្ហាញថាការកំណត់អត្តសញ្ញាណឡើងវិញអាចធ្វើទៅបាន ដែលនៅពេលនោះភាពជឿជាក់របស់អង្គការលើឯកជនភាពត្រូវបានខូចខាតហួសពីសំណុំទិន្នន័យជាក់លាក់នោះ។

**អភិបាលកិច្ចដោយគ្មានម្ចាស់។** គោលនយោបាយអភិបាលកិច្ចទិន្នន័យមានលើក្រដាស ប៉ុន្តែគ្មានបុគ្គលជាក់លាក់ណាទទួលខុសត្រូវចំពោះគុណភាព ឬភាពទាន់សម័យនៃសំណុំទិន្នន័យជាក់លាក់ណាមួយទេ ដូច្នេះស្តង់ដាររិចរឹលដោយស្ងាត់ៗ ហើយគ្មានអ្នកណាកត់សម្គាល់រហូតដល់ទិន្នន័យត្រូវបានពឹងផ្អែកសម្រាប់ការសម្រេចចិត្តដែលវាមិនអាចគាំទ្របានពិតប្រាកដ។ នេះជាការបរាជ័យញឹកញាប់ជាពិសេស ព្រោះឯកសារគោលនយោបាយខ្លួនឯងមើលទៅពេញលេញ បិទបាំងអវត្តមាននៃអ្នកទទួលខុសត្រូវពិតប្រាកដនៅក្រោមវា។

**អន្តរប្រតិបត្តិការដោយបង្គាប់ ដោយគ្មានធនធាន។** គ្រោងរួម ឬគ្រោងលេខសម្គាល់ត្រូវបានកំណត់ជាកាតព្វកិច្ចពីកណ្តាល ប៉ុន្តែមិនដែលត្រូវបានផ្តល់មូលនិធិដល់ក្រុមដែលរំពឹងថានឹងទទួលយកវា ដូច្នេះការអនុលោមក្លាយជាលំហាត់ធីកប្រអប់ — វាលមានតាមបច្ចេកទេស ប៉ុន្តែមិនត្រូវបានបំពេញត្រឹមត្រូវ — ជាជាងអន្តរប្រតិបត្តិការពិតប្រាកដ និងអាចប្រើបាន។ ថ្លៃដើមគឺអារម្មណ៍មិនពិតថាមានស្តង់ដាររួម ដែលរកឃើញតែនៅពេលនរណាម្នាក់ព្យាយាមពឹងផ្អែកលើទិន្នន័យដែលវាត្រូវតែធ្វើស្តង់ដារ។

**ការលាបពណ៌ភាពបើកចំហ (open-washing)។** អង្គការមួយផ្សព្វផ្សាយផ្ទាំងគ្រប់គ្រង និងការបង្ហាញទិន្នន័យសង្ខេប ហើយហៅវាថាទិន្នន័យបើកចំហ ខណៈដែលសំណុំទិន្នន័យអានបានដោយម៉ាស៊ីនដែលភាគីទីបីត្រូវការដើម្បីសាងសង់អ្វីថ្មី នៅតែមិនបានផ្សព្វផ្សាយ ឬបានផ្សព្វផ្សាយក្នុងទម្រង់ដែលគ្មានអ្នកណាអាចប្រើឡើងវិញជាក់ស្តែង។ នេះចាប់យករូបរាងនៃតម្លាភាព និងភាពបើកចំហដែលបានរៀបរាប់ក្នុង ប្រធានបទ 3.4 — គណនេយ្យភាព តម្លាភាព និងភាពស្របច្បាប់ ដោយគ្មានខ្លឹមសាររបស់វា ហើយវាច្រើនតែត្រូវបានច្រឡំជាកម្មវិធីទិន្នន័យបើកចំហពិតប្រាកដ ព្រោះផ្ទាំងគ្រប់គ្រងមើលទៅគួរឱ្យចាប់អារម្មណ៍។
